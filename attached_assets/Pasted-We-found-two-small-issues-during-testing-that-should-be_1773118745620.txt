Issue 1 — Wikipedia search sometimes returns the wrong page

Example test:

User command:
/wiki ariana grande

Expected:
Wikipedia page for the artist
https://en.wikipedia.org/wiki/Ariana_Grande

Actual result returned:
Positions (album) page.

This happens because the wiki service likely performs a search and simply selects the first search result.

Required fix

Improve the wiki lookup logic:
	1.	First try an exact page lookup using the query.
	2.	If that fails, then fall back to search.

Example logic:

try:
wikipedia.page(query)
except:
results = wikipedia.search(query)
use best result

This will ensure that /wiki ariana grande returns the correct artist page instead of an album.

Do not change the response formatting of the wiki command.

⸻

Issue 2 — Incorrect song normalization in some outputs

Example seen during testing:

The bot produced:

Counting — stars

instead of:

Counting Stars

This appears to come from the query normalization logic that converts phrases like:

water by tyla

into:

tyla - water

The normalization logic is incorrectly inserting hyphens in some cases where it should not.

Required fix

Ensure the normalization logic only converts patterns like:

<song> by <artist>

into:

<artist> - <song>

But it must NOT modify titles that are already standalone song names.

Example expected behavior:

Input:
lyrics water by tyla

Output query:
tyla - water

But for:

Counting stars

The query must remain:

Counting Stars

No hyphen insertion.
