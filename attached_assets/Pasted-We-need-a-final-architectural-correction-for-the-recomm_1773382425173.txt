Required final design:

A recommendation must follow the searched track’s actual sonic identity, not the artist’s broad catalog identity.

2) The engine must enforce a strict signal hierarchy:
   - STYLE / SUBSTYLE / MUSICAL FAMILY define the primary ecosystem.
   - PRODUCTION identity refines that ecosystem.
   - ENERGY refines movement inside that ecosystem.
   - MOOD is a secondary ranking signal.
   - Any pool-hint / expansion mechanism must be exploratory only, never dominant.

Each style family / pool must belong to a broader ecosystem group, such as:
   - electronic / synth / dance
   - rnb / soul
   - hiphop / trap
   - indie / alternative
   - rock / band
   - latin
   - classical / cinematic
The source song must first be assigned to one primary ecosystem.
Recommendations should remain inside that ecosystem by default.
Cross-ecosystem candidates should only be allowed when there is strong multi-signal justification.

4) Pool expansion must be bounded.
Any hint-based or mood-based expansion must only search adjacent pools, not unrelated pools.
Expansion must never override the source song’s primary ecosystem.
It may widen the search, but it must not redirect the identity.

5) Style / production compatibility must dominate mood-only similarity.
A candidate from the wrong ecosystem must not outrank a correct-ecosystem candidate just because mood is similar.
Ensure that STYLE + PRODUCTION together clearly outweigh MOOD in the final outcome.

Do not allow mood+energy coincidences to boost candidates from unrelated ecosystems.
